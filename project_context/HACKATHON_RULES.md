## 3. Officially Verified Rules (Non-Negotiable Release Gates)

1. **Timing & Pre-Work Boundary (Rules 7 & 8):**
   * *Allowed Pre-Kickoff:* Architectural planning, notes, data model sketches, diagrams, environment and toolchain setup.
   * *Mandatory Kickoff Boundary:* Main application coding, schema creation, container start, and feature implementation **must begin after October 15, 12:01 AM IST**.
2. **FalkorDB Core Requirement (Rules 2 & 3):**
   * FalkorDB must serve as the primary graph database supporting central product functionality.
   * *No Decoration:* If the application functions identically without FalkorDB, the project fails Rule 3.
3. **Data Boundary (Rule 6):**
   * Strictly public, synthetic, or owned data. Never load private, login-protected, paywalled, or restricted personal data into the graph.
4. **Permitted Third-Party Tools (Rule 9):**
   * Open-source libraries, frameworks, public APIs, templates, and tools are permitted. Original work completed during the event will be judged.
5. **Mandatory Submission Deliverables Checklist (Rule 10):**
   * [ ] **Public source-code repository** on GitHub.
   * [ ] **README** with complete setup instructions, graph data model diagram, and architecture breakdown.
   * [ ] **Cypher queries and/or graph algorithms** on which the product depends documented explicitly.
   * [ ] **Demo video** demonstrating the working application.
   * [ ] **Live deployment** or complete local run instructions.
   * [ ] **Declared competition track(s)** clearly stated in submission metadata.
   * [ ] **Explicit AI disclosure** detailing how AI coding assistants were used (Rule 11).
6. **Technical Comprehension Mandate (Rules 12 & 13):**
   * The participant must understand the submitted code and be able to explain the graph model, queries, architecture, and decisions. Projects generated entirely by AI without participant understanding may be disqualified.
